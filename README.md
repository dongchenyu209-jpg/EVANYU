# 在一起的每一天（精简版）

```
index.html           单文件页面（样式+全部功能）
assets/notify.wav    消息提示音
assets/keepalive.wav 后台保活音（极低音量循环）
```

打开 index.html 即可。部署到 GitHub Pages 时把 `index.html` 和 `assets` 文件夹一起上传。
替换提示音/保活音：直接覆盖 assets 里同名文件。


部署时请一并上传 `sw.js`（手机系统通知需要）。

## 安装为应用（PWA）

用 **Chrome** 打开站点后：
- 底部可能出现「安装到主屏幕」横幅，或
- 设置里点「安装到主屏幕（应用）」，或
- 浏览器菜单 ⋮ → **安装应用**

部署时请上传：`index.html`、`sw.js`、`manifest.webmanifest`、`assets/`（含图标与音频）。
需 **HTTPS**（GitHub Pages 自带）才能安装和推送通知。


## 主动发消息（参照「传讯」）

传讯设置 → 节奏：「主动发消息给我」开关 + 「间隔」（1~180 分钟，固定间隔）。
每隔 N 分钟，TA 会先把你没读的消息标为已读，显示「正在输入…」，再发 1~3 条（75% / 约 24% / 约 1%）。
第一条按「最快/最慢回复」的等待时间，连发的后面几条间隔 4 秒 ~ 1 分钟随机。
App 开着才会计时；改了设置或重新打开 App，从那一刻起重新计。聊天页右上角的 💌 按钮是手动触发同一套逻辑。

## 发布新版本时

改了 index.html 之后，把 `sw.js` 第二行的 `CACHE = 'love-diary-v2'` 版本号 +1（v3、v4…），旧缓存会自动清掉。

## 陪伴空间里聊天

一起学习 / 一起睡觉进入陪伴空间后，TA 会隔一会儿主动说一两句（用字卡库），你在下方输入框回，TA 几秒后回应。
右上角「TA 说话」按钮切换：偶尔 / 常聊 / 安静。空间收起后，右下角有「陪伴中」小按钮可回到空间。
这里的消息也会记进传讯聊天记录。

## 塔罗

进入抽牌页会先洗一遍牌（带动画），洗完牌堆一张张发出来；点「↻ 洗牌」可重洗。
设置 → 塔罗 AI 解读：填好接口信息后开开关会自动保存；接口 60 秒没回应会提示失败并改用本地简版解读。

## 主页组件栏 / 娱乐

主页「LOVE METER」下面是可左右翻页的组件栏：日期+今日天气、喝水/吃饭/睡觉打卡、待办（点勾完成、✕ 删除）、娱乐入口。
长按组件约 0.6 秒进入编辑：◀ ▶ 调顺序，✕ 隐藏，下方点「＋ 组件名」加回来，点「完成」退出。
天气用 Open-Meteo（免费、不要 Key）；点「设置城市」输入城市名，或点 📍 用当前位置（固定住，想更新再点一次）；需要联网，定位需要 HTTPS。
娱乐：飞行棋（简化版：一人一架，掷 6 起飞）/ 五子棋 / 猜数字 / 消消乐（各走 8 步比分）。开局抽签定先手，TA 每步随机想 1~30 秒再纯随机出手。

## 筛查不能整曲播放的歌
一起听歌面板里点「🔍 筛查不能整曲播放的」，它会一首一首试（进度显示在下面的小字里），把「接口没给地址 / 被拦下 / 只有试听」的歌列出来，带原因。勾选后点「删除勾选的」就能从歌单里踢掉，歌单本身不会被改，只是本地这份列表少几首。歌曲多的话会慢一点（一首几百毫秒到几秒），中途可以关掉面板，已经筛查完的结果会留着。


## 用官方外链播放器播整曲（合规）

在「一起听歌」面板里点 **🎧 官方外链播放：关** 把它切到「开」，
就会用网易云**官方提供**的嵌入播放器（music.163.com/outchain/player）来放当前这首歌。

- 这是官方给第三方网站用的播放器，属于正规外链，不碰任何登录态。
- 免费曲目通常能整曲播放；VIP 曲目要放整曲，需要**你本机的浏览器里已经登录过网易云**，
  并看官方播放器本身是否放行；否则官方播放器只会给试听片段。
- 官方模式下，App 内的进度条 / 拖动 / 播放暂停不可用（进度由官方播放器自己控制）；
  上一首 / 下一首会重新载入对应歌曲的官方播放器。
- 关掉这个开关，就回到原来的直链播放模式。

## 更新（v44）· 筛查提速
- 并发 6 路探测（原来是单首排队），单首最长等待由 12s 降到 6.5s，失败原因诊断超时 9s 降到 3.5s。

- 筛查时显示进度条与已用时。

## 更新（v45）· 删掉官方外链播放器
- 现象：在官方外链模式下每首歌都提示「没有网易云 ID」，一律放不了。
  原因：歌单是从第三方 meting 接口拉的，返回项里没带 `id` 字段，官方播放器就拿不到 ID。
- 处理：**整条官方外链播放器路径已删除**（开关按钮、iframe、切歌分支、相关函数全部移除）。
  现在「一起听歌」只有一条路：直链播放（`song.url`），配合 🔍 筛查与 🔀 随机。
- 若歌单里某些歌没有直链（`url` 为空），会提示「这首没有可播放链接」，可用 🔍 筛查一次性挑出来。

## 更新（v46）· 筛查结果永久缓存
- 之前筛查的「能不能整曲播放」结果只存在内存里，刷新/重开就清空，下次还得重探。
- 现在结果会写进 **IndexedDB 持久化**（键 `EVAN:vinylProbeCache`，纯本地、不走云端），
  关掉页面/重开 App 后依然在，下次打开筛查基本秒回。
- 缓存有效期仍是 6 小时；最多保留 3000 条，超出自动丢最旧的；读写出错会自动降级，不影响使用。

## 更新（v47）· 筛查结果永久记住
- 上一版缓存有 6 小时有效期，过一会儿又得重探。本版**直接取消过期**：
  同一首歌探过一次就**一直记住**，不再因超时被清掉（想重探点面板里的「重新筛查」即可）。
- 另外改成**边查边存**：每探完一首（节流 3 秒）立刻写进 IndexedDB，
  所以就算筛查中途关掉页面/退 App，已经查过的部分也不会丢，下次接着用。
- 上限仍是 3000 条（超出丢最旧），读写出错自动降级，不影响使用。

## 更新（v48）· 多音源播放修复（重要）
- **修复「一进去就自动滑动、全都播不了」**：
  - 原因：原来的音源接口 `api.injahow.cn` 已失效（返回「请求次数已达上限」），所有歌都播不了；
    播放器一遇到失败就 800ms 自动跳下一首，于是变成「一直自动滑动」。
  - 现在：**连续 3 首「所有音源都试过仍失败」就自动停下**，不再无限跳歌，并提示你去点重取按钮。
- **新增多个备用音源镜像**（一首歌会依次尝试）：
  1. `api.qijieya.cn`（实测稳定，**首选**）
  2. `api.injahow.cn`（原来的，留作备用）
  3. `api.i-meto.com`（备用）
  同一首歌只要任一音源能放，就自动用那个，并把这个稳定链接记下来。
- **新增两个手动兜底按钮**（听歌面板内）：
  - 「🔄 重新获取播放链接」：给当前这首重取链接（会试所有音源），接口恢复了点一下就能救活。
  - 「🔄 全部重取链接」：给整张歌单逐首重取，旧歌单一次救活。
- **筛查逻辑改造**：现在「筛查」= 把这首歌的**每个音源都试一遍**，
  全部失败才判「放不了」并筛掉；只要有一个能放就保留（并回写可用链接）。
- **缓存 key 升级**（`EVAN:vinylProbeCache:v2`）：让 v47 之前因单音源失效而误判「放不了」的永久记录**全部失效**，
  强制用多音源重新判定，不会再「明明能放却一直被跳过」。
- 说明：装 v48 后 sw 版本号变了，会**自动覆盖安装并更新**，无需手动卸载。

## 更新（v51）· 群聊改为「多位伙伴」真实回复（重做 v50）
- v50 的「群聊」是**显示层换马甲**：每条 AI 消息存库时发件人恒为梦角，渲染时再按消息 id 哈希套上成员名字，结果**开启后连旧聊天记录也被改名**。此机制已废弃。
- v51 改为参考包 `partnerPersonas` 的真实指派机制：**每轮回复前约 30% 概率随机抽中一位伙伴**，被抽中的人**真正写进该条消息的发送人**（sender / senderAvatar），其余约 70% 仍是默认梦角。
- 效果：每位伙伴是**独立的人**，大家**共用同一个字卡库**，但**在不同时间**以各自的名字/头像回你；历史消息**永不改写**，没被抽中的（含旧记录）始终是默认梦角。
- 「👥 管理伙伴」可增删改伙伴（名字 + 可选头像，不上传则用名字首字彩色圆点）；可单独控制是否显示伙伴名字。关闭开关或列表为空时，完全退回单人显示。
